CONTINUOUS AUTHENTICATION

Watchdog for the untrusted workspace.

SentinelGuard is a Windows agent that verifies who is sitting in front of the machine every few seconds - on-device, with no network and no cloud. When verification fails, the screen protects itself: it contains, alerts, and escalates to the real OS lock.

THE THREE STATUSES

The agent is always in exactly one status, and the status is what the operator sees on the dashboard. Escalation is one-way - you never skip a step - but recovery is automatic wherever it is safe to be automatic. The order is SCANNING → PRIVACYMODE → LOCKDOWN.

SCANNING

The normal, working status. The enrolled user has been matched in the last verification pass and the trusted anchor is in range, so nothing is hidden and nothing is blocked - the agent simply keeps checking in the background.

PRIVACYMODE

Containment inside the application layer: the work is covered but the session stays alive. Nothing is closed, nothing is lost, and the agent keeps watching for the enrolled face so it can hand the desk straight back.

LOCKDOWN

The last status, and the only one the agent cannot undo. Containment is handed to the operating system lock, so the desk is protected even if the agent, the camera or the machine's power state changes.

LAYER 1  ·  SIGNALSsenses, never judges
MonitoringService

Camera frames, face detection, then a 512-D embedding compared against the enrolled user. Publishes authorized_user.

TrustedNodeService

A trusted beacon in the room, matched on its identifier and signal strength. Publishes node_signal.

↓
LAYER 2  ·  EVENT SERVICEclassifies, never judges
NONE
Nothing is wrong: the enrolled user is matched, no other face is in frame, and the anchor is in range.
ON_USER_ABSENT
The enrolled face has not been matched for the length of the absence timer - the seat is empty, or whoever is in it is not the user.
ON_OBSERVER
A second face is in frame alongside the verified user and stays there for three continuous seconds. Someone glancing past never crosses the threshold.
ON_NODE_LOSS
The trusted anchor has missed two consecutive scan passes - roughly twelve seconds - so the machine is no longer in the room it is supposed to be in.
ON_UNSECURE_ENV
An unrecognised face is at the machine with no verified user present. Not an onlooker - someone using the desk.

Every event is debounced before it is raised, so a dropped frame or a moment of bad light never triggers anything. The result is a set, not a value - several events can be true in the same pass, and Sentinel resolves them by priority.

↓
LAYER 3  ·  SENTINELthe only decision maker
decide(state, events) → (state, commands)

One pure function holds the priority order, the single configurable timer, and every escalation path.

↓
LAYER 4  ·  ACTIONSexecutes, never judges
Notify

Raises an on-screen warning naming what was seen and writes a timestamped entry to the audit log. Nothing on the desk changes - this is the action for things the user should know about but does not need protecting from.

Contain

Minimises open windows, covers the desktop with an opaque overlay and absorbs keyboard and mouse input, so nothing can be read or typed. The session keeps running underneath and is handed back intact on the next verified match.

Lock

Hands the screen to the operating system's own lock. The agent stops being the thing standing in the way, which means the protection survives the agent being killed - and only a real sign-in returns the desk.
